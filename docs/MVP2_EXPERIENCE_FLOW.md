# MVP2 体验流程｜笑一下蒜鸟 SuanBird

## 1. 体验定位

MVP2 的核心体验是：用户把一段糟心事丢进来，系统先把情绪和槽点拆开，再快速给出一个可笑、可保存、可继续生成的表情包结果。

它不是重社交产品，也不是单纯的 AI 绘图工具，而是一个轻量的情绪出口：

```txt
说出糟心事
-> AI 帮你归纳槽点
-> 生成丑萌反派或自嘲形象
-> 给出一句带反差的文案
-> 保存成图或再来一张
```

用户感受到的价值应该是：

- 先被理解：我的吐槽被准确拆成场景、情绪、标签和梗点。
- 再被逗笑：讨厌的人或事被变成一个荒诞形象。
- 最后被托住：系统给一句反向夸夸或自嘲式缓冲，不把情绪推向攻击。
- 可以带走：结果能保存、能回看、能重新生成。

## 2. 主体验流程

### 2.1 进入页面

用户打开页面后，第一屏直接看到生成工具，不进入营销介绍页。

页面首屏信息：

- 产品名：笑一下蒜鸟。
- 一句话说明：AI 即时解压表情包生成器。
- 输入框：今天想吐槽什么？
- 生成模式：发泄 / 自嘲。
- 模板选择：自动匹配或手动选择模板。
- 操作按钮：语音、生成表情包。

体验目标：

- 用户 10 秒内知道这里能做什么。
- 用户不需要注册、不需要学习复杂规则。
- 默认配置已经可用，用户只要输入文字即可开始。

### 2.2 输入槽点

用户可以通过两种方式输入：

1. 文字输入：直接在文本框里写一段糟心事，最长 1000 字。
2. 语音输入：点击“语音”开始说话，再点击“停止”结束，系统把语音转成文字。

输入区需要降低启动成本：

- placeholder 随机给出现实吐槽示例。
- 计数器提示当前字数。
- “清空”按钮支持快速重写。
- 语音不可用时提示用户改用手动输入。

典型输入示例：

```txt
开会讲了两小时，最后发现没人知道要干嘛，还让我整理会议纪要。
```

### 2.3 选择生成模式

用户输入后，可以选择两种模式。

| 模式 | 用户意图 | 生成重点 | 适合场景 |
|---|---|---|---|
| 发泄 | 想把糟心对象变成可笑反派 | 被吐槽对象、反派形象、吐槽梗图文案 | 甩锅、画饼、插队、噪音、客服绕圈 |
| 自嘲 | 想轻轻调侃自己的状态 | 用户处境、情绪状态、反向夸夸 | 加班低电量、社交疲惫、生活小崩溃 |

默认进入“发泄”模式，因为它更符合“吐槽一下”的即时爽感。

### 2.4 选择图片模板

模板选择默认是“自动匹配”。用户也可以手动选择当前工程注册的模板：

| 模板 | 体验方向 |
|---|---|
| 黑白怪物图鉴 | 强讽刺、图标化、适合甩锅和插队 |
| 动物变种图鉴 | 把槽点嫁接到动物原型上 |
| 毛球怪手绘系列 | 固定毛球怪主角，轻手绘表达 |
| 糖果色吐槽小怪物 | 软萌、生活化、适合轻吐槽 |
| 贴纸感表情怪物 | 聊天贴纸感，适合社交传播 |
| 夜色刮刻怪物 | 更尖锐、更有地下海报感 |
| 蒜鸟日常状态格 | 固定蒜鸟 IP，适合自嘲和轻状态 |

模板选择的体验原则：

- 不强迫用户理解模板参数。
- 自动匹配优先保证出图稳定和场景贴合。
- 手动选择用于 demo、风格控制和“再来一张”玩法。

### 2.5 点击生成

用户点击“生成表情包”后，页面进入生成状态。

系统动作：

1. 校验输入是否为空。
2. 对文本做安全检查和必要脱敏。
3. 组装生成请求：

```js
{
  text,
  sourceType: "text" | "speech",
  generateMode: "vent" | "self",
  templateProfileId: "auto" | templateId,
  timestamp
}
```

4. 先调用文本生成链路。
5. 文本结果返回后立刻展示结果卡片。
6. 再继续后台补齐图片生成。

这个阶段的体验重点是：用户不要面对一整段空白等待。

### 2.6 文案先出

MVP2 采用“两段式生成”：

```txt
generateTextResult()
-> 先展示结构化文案
-> completeImageForResult()
-> 图片生成完成后替换占位图
```

文案先出时，结果卡片展示：

- 标题或槽点摘要。
- 场景、情绪、关键词标签。
- 表情文案。
- 反派形象或自嘲形象。
- 图片提示词。
- 动画提示词。
- 图片生成中的 loading 状态。

用户感受到的是：

```txt
AI 已经理解我了，图还在生成。
```

这比“点完按钮等到最后才出现结果”更适合现场演示，也更稳。

### 2.7 图片补齐

图片生成成功后，结果卡片更新为最终状态。

最终卡片展示：

- 生成完成状态。
- 反向夸夸或核心文案。
- 生成图片。
- 场景标签和情绪标签。
- 摘要。
- 提示词详情折叠面板。
- 生成模式。
- 图片模板。
- 输入来源和生成时间。
- “再来一张”按钮。
- “保存图片”按钮。

如果图片生成失败，页面保留本地模板图和已生成文案，并提示：

```txt
图片生成失败，已保留本地模板图
```

这样 demo 不会因为图片接口失败而中断。

### 2.8 保存图片

用户点击“保存图片”后，系统下载当前结果图片。

保存文件名格式：

```txt
tu-cao-{resultId}.{png/jpg/webp/svg}
```

保存成功后显示轻提示：

```txt
图片已保存。
```

如果保存失败，提示用户截图兜底：

```txt
保存失败，可以先截图兜底。
```

### 2.9 再来一张

用户点击“再来一张”后，系统沿用当前吐槽文本、生成模式和模板选择，再生成一个新结果。

体验价值：

- 同一个槽点可以换一种表达。
- 适合现场连续展示不同模板效果。
- 用户不会被迫重新输入。

### 2.10 历史回看

页面底部展示最近生成结果，当前限制为最近 3 张。

历史条目展示：

- 缩略图。
- 场景或标题。
- 摘要或夸夸文案。

用户点击历史条目后：

- 当前结果切回该历史卡片。
- 输入框回填原始文本。
- 生成模式回填。
- 模板选择回填。
- 输入来源回填。

体验目标：

- 用户可以快速比较最近几次结果。
- 用户可以从旧结果继续修改和再生成。
- 历史是轻量回看，不做复杂账号系统。

## 3. 页面状态流转

```txt
空状态
-> 输入中
-> 生成中
-> 文案已出，图片生成中
-> 图片完成
-> 保存 / 再生成 / 历史回看
```

| 状态 | 触发条件 | 页面表现 | 用户可做 |
|---|---|---|---|
| 空状态 | 首次进入或未生成 | 只展示输入工具和最近生成空提示 | 输入文字、语音输入、选模式、选模板 |
| 输入中 | 用户正在编辑文本 | 字数更新，按钮可用 | 清空、生成、切模式、切模板 |
| 生成中 | 点击生成后 | 输入区禁用，按钮显示生成中 | 等待 |
| 文案已出 | 文本结果返回 | 展示分析结果，图片 loading | 阅读文案，等待图片 |
| 图片完成 | 图片生成成功或兜底完成 | 展示图片和操作按钮 | 保存、再来一张、查看提示词详情 |
| 历史回看 | 点击历史条目 | 切换结果并回填输入区 | 保存、再生成、修改 |

## 4. 关键分支流程

### 4.1 语音输入流程

```txt
点击语音
-> 浏览器请求语音能力
-> 开始计时和波形动画
-> 用户点击停止
-> 系统整理语音
-> 转写成功后回填输入框
-> sourceType 标记为 speech
```

兜底：

- 浏览器不支持语音能力：提示语音不可用，请手动输入。
- 用户未说出有效内容：输入框不变。
- 语音成功转写后，本次生成结果显示“输入来源：语音转文字”。

### 4.2 发泄模式流程

```txt
用户选择发泄
-> AI 找出被吐槽对象
-> 生成反派称号、反派形象、道具和动作
-> 转成表情包文案和图片提示词
-> 展示为可笑的槽点反派
```

发泄模式的体验边界：

- 可以吐槽行为，不鼓励攻击真实个人。
- 生成对象要抽象成怪物、状态或道具化形象。
- 文案要好笑，但不走辱骂、威胁或人身攻击。

### 4.3 自嘲模式流程

```txt
用户选择自嘲
-> AI 理解用户处境和情绪
-> 生成用户状态类形象
-> 给出更温和的反向夸夸
-> 形成可分享的自嘲表情包
```

自嘲模式的体验边界：

- 不否定用户。
- 不把问题都归因到用户身上。
- 重点是“我好累但我还挺可爱/挺清醒”。

### 4.4 返回修改流程

用户在文案先出阶段点击“返回修改”后：

```txt
结果文本回填到输入框
-> 模式和模板回填
-> 页面滚动到输入区
-> 用户继续编辑
```

如果用户已经进入最终卡片，也可以点击历史条目让输入框回填，再直接在输入框里继续改写。

适合场景：

- 用户觉得槽点没说清。
- 用户想换一种口吻。
- 用户想把攻击性词语改得更轻。

## 5. 异常与兜底体验

| 异常 | 页面提示 | 兜底策略 |
|---|---|---|
| 输入为空 | 先写一句想吐槽的事。 | 不发起生成 |
| 语音不可用 | 语音不可用，请手动输入。 | 回到文字输入 |
| 内容风险较高 | 返回脱敏后的兜底结果 | 标记“已脱敏”，不生成攻击性内容 |
| 文本 AI 失败 | 生成出错了，已经切换到兜底结果。 | 使用本地规则结果 |
| 图片生成失败 | 图片生成失败，已保留本地模板图 | 文案可用，图片用本地模板图 |
| 保存失败 | 保存失败，可以先截图兜底。 | 用户可手动截图 |

兜底体验原则：

- 不让用户卡死在错误状态。
- 文案优先于图片，先保证有内容可展示。
- 所有失败提示都保持轻量，不暴露复杂技术错误。

## 6. 30 秒演示脚本

推荐演示路径：

1. 打开页面，停留 2 秒展示产品名和输入区。
2. 输入一段明确槽点：

```txt
开会讲了两小时，最后发现没人知道要干嘛，还让我整理会议纪要。
```

3. 保持默认“发泄”和“自动匹配”，点击“生成表情包”。
4. 文案先出时口播：

```txt
这里先把槽点、标签、反派形象和表情文案生成出来，图片在后台继续补齐。
```

5. 图片完成后展示最终卡片。
6. 点击“再来一张”，说明同一槽点可以换风格。
7. 点击历史条目，展示最近结果可回看。
8. 点击“保存图片”，完成闭环。

备用演示槽点：

```txt
地铁上被挤到变形，旁边的人还在外放短视频。
```

```txt
朋友迟到四十分钟，还说我太较真了。
```

```txt
快递显示已签收，但我连盒子的影子都没见到。
```

## 7. 验收走查清单

### 主链路

- 页面打开后不登录即可使用。
- 输入文字后可以正常生成。
- 发泄 / 自嘲模式都能产出差异化文案。
- 自动匹配模板可用。
- 手动选择模板可用。
- 文案先出，图片生成中状态可见。
- 图片完成后保存按钮可用。
- 再来一张可复用原槽点。
- 最近 3 张历史可以点击回看。

### 兜底链路

- 空输入不会发起生成。
- 语音不可用时能回到文字输入。
- 图片失败时仍有文案和本地模板图。
- 保存失败时有截图兜底提示。
- 高风险输入不会生成具体攻击内容。

### 演示效果

- 30 秒内能完成输入、生成、保存。
- 结果卡片有明确场景感和表情包感。
- 文案不是空泛鸡汤，能对应用户吐槽。
- 图片风格和所选模板一致。
- 页面状态提示清楚，不需要讲解才能理解。

## 8. 答辩口径

MVP2 把“吐槽一下”的单次生成闭环做得更像真实可玩的产品：用户可以用文字或语音输入一段长吐槽，选择发泄或自嘲，再由 AI 先给出结构化理解和表情包文案，图片在后台继续生成。这样既减少等待感，也保证现场 demo 稳定。最终用户可以保存图片、再生成同一槽点的不同版本，并从最近历史里回看结果。

我们保留了情绪释放和社交传播感，但把攻击性表达收束为丑萌形象、场景标签和反向夸夸，让产品既好笑、可分享，又尽量避免挂人和网暴风险。
